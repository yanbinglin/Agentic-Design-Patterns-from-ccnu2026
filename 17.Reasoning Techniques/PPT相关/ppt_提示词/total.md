# 01_cover

【0:00–1:00】开场不解释概念，直接提问。

要讲的一整晚，其实只有一个问题：我们到底在什么时候，让模型「想」一下？不是「模型要不要更大」，而是「回答之前，要不要先摊开推理」。这一章给的不是一个技巧，而是一条谱系：会想、会查错、会动手、会协作，四台阶，加一条推理扩展定律，再加一个已经上线的形态。

[停一拍] 底部的四台阶尺子现在全是空心的——还没有任何一级被点亮，这是我们今晚要走的路。

页脚给了出处：中文双语 PDF，第 17 章，pp.207–224。全部内容只来自这一章，不夹带外部数据。

# 02_hook_24point

【1:00–2:30】用一个人人都见过的失败开场。

24 点，四个数字。直接问模型要一个答案，它会非常自信地给你一个式子，而那个式子是错的。左边的纸面上，答案被红笔划掉了。右边是同一道题：先把步骤写出来，再按步骤算，答案对上了。

差别不在知识——模型两遍都知道怎么算。差别在于推理有没有被显式地写出来。这就是整章的第一性原理。

当场可做：同一道题问两遍，第二遍加一句「一步一步想」，两分钟以内，听众会亲眼看到差别。

[演示点 1] 如果现场网络不稳，跳过演示，只讲这一页的对照，照样成立。

# 03_map_four_steps

【2:30–4:00】把这张地图立起来，后面所有页都挂在它上面。

台阶一「会想」：让它把推理写出来——CoT、ToT。台阶二「会查错」：让它检查并修正自己——Self-Correction、PALM。台阶三「会动手」：让它调工具、边做边看——ReAct。台阶四「会协作」：让多个模型互相挑错——CoD、GoD、MASS。

右侧两个框是用途：蓝图是「怎么选」，Deep Research 是「已经长成什么样」。上面那条横线是这一章的定律：思考不是免费的，它可调、有价。

[指一下尺子] 从这里开始，尺子会一页一页被点亮。

# 04_cot_tot

【4:00–5:30】台阶一，但不要把它讲成「加一句提示词」。

CoT 是线性推进：一步接一步，把中间结论留在纸面上，后面的步骤才有东西可依。右边那张竖式就是最朴素的样例——不是模型不会算，是它没有草稿纸。

ToT 换了结构：不再是单链，而是分叉、评估、剪枝、必要时回溯。像走迷宫时同时探几条路，走不通就退回上一个岔口。代价是调用次数上去了，所以它适合「答案空间大、一次想不清」的问题。

一句话收：CoT 买的是「可追踪」，ToT 买的是「可试探」。两者都不是万灵药，简单任务上它们只是更慢。

# 05_selfcorrection_palm

【5:30–7:00】台阶二：从「想出来」到「想对了」。

左边是一个闭环：起草、复查、修订，用红笔把问题圈出来再改。关键在「复查」这一步要有可核对的对象——有测试就跑测试，有约束就查约束，什么都没有就只能靠模型自评，而自评很容易自我肯定。这是自我纠正最常见的失效点，必须点破。

右边 PALM 把这件事拆成两半：语义理解在前，运行执行在后，先在语义层把方案想清楚，再交给运行层去跑。绿色那一块是执行，不是思考——这个颜色约定全场通用：绿色代表外部工具或确定性执行。

[半格标记] 尺子上第二格已经点亮一半：自我纠正在很多系统里是可选件，不一定每页都用。

# 06_react_cycle

【7:00–8:30】台阶三：会动手。这一页是全场的技术转折点。

三角形三个角：思考、行动、观察。行动去调工具，观察把结果拿回来，再回到思考。它不是「想完再做」，而是「边做边想」。

左边那条绿线是知识库接进「行动」这一步——模型查的不是自己的记忆，是外部资料。

下面的代码块是它的骨架：thought → action → observation，循环直到收敛。旁边那个「边查边写」的小例子说明它的手感：先查一页资料，写两段，发现不对再回去查。

一句话收：从这一页开始，「只会想」变成「能干活」。这也是 Deep Research 那类产品真正的地基。

# 07_rlvr_thinking_budget

【8:30–9:30】台阶三的后半段：思考本身变成了可训练、可调的东西。

两个条件必须同时成立：第一，任务有可验证的答案（算得出对错、跑得过测试）；第二，能给出可训练的奖励信号。缺一个，RL 就训不起来。这就是为什么数学、代码先突破，而开放式写作没有。

RLVR 的做法是让模型反复试错，答对了加分，于是它自己学会「多写几步再答」——长思维链不是被教出来的，是被奖励出来的。

结果是一个属性变了：思考预算从「提示词的写法」变成了「模型的旋钮」。短轨迹几百 token，长轨迹几千 token，同一道题，你可以选花多少。

[串场] 这条轴不是比喻。下一页就把它跑了一次：同一个模型、同一句提示词，多花十七分钟能买到什么？

# 08_single_agent_pelican

【9:30–10:30】台阶三收尾：把上一页那条「思考预算」的轴，用一次真实运行量出来。

先把条件说清楚，免得被听成模型对比：同一个部署算力有限的模型、同一个单智能体、同一句提示词——「生成一只骑自行车的鹈鹕的 SVG 动图」。两侧唯一变化的是推理配置。

A 侧只做内部推理：模型自己想，步骤不外显，直接把 SVG 写出来，不到 3 分钟交卷，全程没有触发上下文压缩。B 侧使用推理技术：把推理显式写出来，边做边自我修正、分步验证，跑满 20 分钟，中途触发了一次上下文压缩。

两张图都是真的在动：PPT 里显示的是首帧，想看看动起来的样子，就翻现场预览或者回看 images/A.svg、images/B.svg。A 是一层天空、转动的轮子和踏板；B 多出了云、山丘、路缘三层滚动背景，画面左下角还留了一行标题 PELICAN EXPRESS。

一句话收：思考预算不免费。多花的十七分钟买到的是场景层次和部件联动，代价直接写在时间和上下文上——所以它是可以拧的旋钮，不是越大越好。

[串场] 一个智能体已经先把自己榨到这条线了。再强的单模型也有盲区——下一段：能不能让几个模型互相挑错？

# 09_cod_god

【10:30–12:00】台阶四：会协作。两句话讲完两个层级。

CoD 是 AI 版的同行评审：几个模型各自提案，互相挑毛病，再相互反驳，一轮一轮改。关键是「挑毛病」必须具体——说不出哪里错，就等于没批评。

GoD 把这场辩论画成图：节点是论点，边是支持或反驳。结论不是投票投出来的，而是取自「证据最强的那个论点簇」——红色虚线圈住的那一簇。反驳边单独成群，不会并进结论。

买到什么：更高的准确率，更低的单模型偏见。代价是调用次数成倍上升。

[深浅] 偏业务的听众记住 CoD 这一句就够；偏工程的再讲 GoD 的图结构。

# 10_mass_principles

【12:00–13:00】这一页给的是「别再靠手感调提示词」。

MASS 把「提示 + 拓扑」当成一个可搜索的优化问题，三步走：先做块级提示优化，把每个角色的提示调好；再做工作流拓扑优化，搜哪条边、哪个顺序更好；最后做工作流级联调，把整条链放一起调。

更要紧的是抽出来的三条原则，右边的编号清单：先优化个体，再围绕高影响力拓扑搜索，最后做系统级微调。顺序不能反——个体没调好就去调拓扑，是在错误的基座上搜索。

[深浅] 原文把 MASS 标为可选进阶。时间紧就只讲这三条原则，它们是免费拿走的。

# 11_scaling_law_triangle

【13:00–14:30】这是全场最该被记住的一页，也是预算决策者唯一必须听的一页。

推理扩展定律说的是一句朴素的话：性能 = 模型能力 × 思考预算，而不只是模型大小。你愿意在推理阶段多花的算力，是另一项可调参数。

但三角形没有免费的角：模型规模、响应延迟、运营成本，三者互相拉扯。想更大就更贵，想更久就更慢，想更省就得多想。

中间那个反例很重要：小模型 + 多次采样 + 自洽投票，有时候能反超「大模型 + 单次生成」。所以问题不是「要不要上最大的模型」，而是「哪一角你愿意付费」。

[边界] 推理链越长，延迟和 token 成本越高。不是所有场景都值得——客服秒回和离线调研，答案完全不同。

# 12_deep_research_flow

【14:30–15:30】从定律回到现实：这套东西已经长成产品了。

左边是两种形态的对照：传统搜索秒回一串链接，综合留给你自己；深度研究花掉几分钟预算，还你一份写好的报告。

右边是四步：初始探索、推理精炼、跟进查询、终稿综合。注意第二步——「推理精炼」不是再搜一轮，而是先判断缺口在哪、哪里有矛盾，再去补。这四步就是前面几页技术的组合：显式推理、自我纠正、工具调用。

品牌只作为事实陈述，不构成推荐。

# 14_three_takeaways

【16:30–17:30】收束成三句话 + 三条边界。

第一句：复杂的任务，先问「这需不需要显式推理」。需要拆步、多跳、调工具、按反馈改方案，就用；简单任务直接答更快更便宜。

第二句：先把思考预算花掉。预算是最便宜的杠杆——比换更大的模型省钱，也更容易回退。

第三句：从单体走到协作。显式推理 + ReAct 闭环 + 多智能体审议，才是能托付的自主系统。

下边三条边界同样要说：延迟和成本会涨；长时自主执行需要引用、可审计轨迹和护栏；这门课只讲第 17 章。

# 15_two_options_close

【17:30–18:30】最后不总结，给选择。

A：低成本升级现有功能，顺序是 CoT → ReAct → Self-Correction，改动最小，这周就能上线。B：立项一个 Deep Research 式的内部调研助手 demo，投入更大，也更能摸到能力边界。

两个选项用同一套标准判定：本周能改动多少、谁能在本周验证、它能证明什么。

裁决顺序只有一条：先榨干单智能体，仍不够再上多智能体——不要一开始就加角色。

不动的代价也要说清楚：一口气回答会继续产出无法审计的错答案。
