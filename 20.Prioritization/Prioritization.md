# Chapter 20: Prioritization 优先级排序

> 来源为本目录的《Chapter20_Prioritization.pptx》。笔记按主题整理课件正文及讲者备注中的技术内容。

## 1. 智能体为什么需要优先级排序

**优先级排序（Prioritization）**帮助智能体在多个目标或行动竞争有限资源时，决定先做什么。比如，系统故障修复、回复客户邮件、更新项目文档和准备会议材料同时进入待办队列时，智能体需要结合当前目标、任务影响和执行条件安排顺序。

### 1.1 六个判断维度

| 维度 | 判断问题 | 项目管理示例 |
| --- | --- | --- |
| 紧急程度 | 距截止时间还有多久？ | 故障修复窗口即将关闭 |
| 重要程度 | 对当前目标有多大影响？ | 故障直接影响核心服务 |
| 依赖关系 | 任务是否阻塞后续工作？ | 接口就绪后才能联调 |
| 资源可用性 | 工具、信息和人员是否就绪？ | 修复仍在等待权限或值班人员 |
| 成本与收益 | 这项投入能带来什么收益？ | 优先修复影响范围更大的问题 |
| 用户偏好 | 用户希望怎样取舍？ | 优先满足用户明确提出的交付偏好 |

### 1.2 四阶段流程

1. **定义标准**。明确当前目标及任务间的比较依据。
2. **评估任务**。逐项判断影响、时限、依赖和资源条件。
3. **选择行动**。根据排序及实际可执行性决定下一步。
4. **动态调整**。新事件、截止时间、资源状态或目标变化后，重新评估待办任务。

### 1.3 三个决策层级

| 层级 | 要决定什么 | 系统故障示例 |
| --- | --- | --- |
| 目标（Goal） | 先实现哪个目标？ | 优先恢复服务 |
| 子任务（Sub-task） | 计划中的哪项工作先做？ | 先定位故障原因 |
| 当前行动（Immediate Action） | 现在执行哪一步？ | 读取相关日志 |

当目标、子任务或候选行动有竞争，且执行顺序需要随环境调整时，可以在对应层级应用同一套排序流程。

## 2. 两个动态调度案例

### 2.1 云资源调度

在需求高峰期，课件将三项任务排为**在线服务扩容 → 常规资源调整 → 离线批处理**。在线服务接近容量上限，影响在用用户。常规调整仍有价值，紧迫性较低。离线批处理可移到低峰期。

任务排到队首后，智能体先检查配额与可用节点容量。资源充足时执行扩容，并查看服务延迟是否改善。配额不足时，当前行动改为申请配额或按调度规则释放可让出的容量，满足前置条件后再扩容。

### 2.2 网络安全告警

初始队列为 **A（异常登录）→ B（漏洞告警）→ C（异常流量）**。监测发现 C 涉及支付系统后，智能体按威胁严重程度、潜在影响与资产关键性重新评估，队列更新为 **C → A → B**，先核查支付系统流量。

核查结果写回监测状态。若流量来自已知运维变更，C 的优先级可能下调。若异常持续，则可能需要继续优先处理。每轮响应产生的新证据可用于下一轮排序。

## 3. Project Manager Agent 示例

### 3.1 组件和任务记录

| 组件 | 职责 |
| --- | --- |
| `ChatOpenAI` 模型、系统提示和对话记忆 | 理解用户请求，按提示规则结合历史消息判断优先级和负责人 |
| LangChain `AgentExecutor` | 组织工具调用并返回回复和任务列表 |
| 任务工具 | 创建任务、设置优先级、分配负责人和查询任务 |
| `SuperSimpleTaskManager` | 用内存字典按编号保存任务描述、优先级与负责人 |

优先级约定为 **P0 最高、P1 中等、P2 最低**。对话记忆保存交互上下文，任务管理器保存可以由工具读写的业务字段。

### 3.2 一次请求的工具调用顺序

1. 调用 `create_new_task`，根据任务描述创建记录并取得编号。
2. 设置优先级，检查等级是否为 P0、P1 或 P2，再写入该编号对应的记录。
3. 给同一编号分配负责人。信息缺失时，按示例的系统提示补齐默认值。
4. 调用 `list_all_tasks`，查看更新后的任务状态。

| 用户请求 | 优先级与负责人 | 依据 |
| --- | --- | --- |
| 尽快实现新登录系统，交给 Worker B | P0 / Worker B | 按示例规则将紧急表达映射为 P0，并采用指定负责人 |
| 审阅营销网站内容 | P1 / Worker A | 未指定等级和负责人，采用课件中的默认示例 |

这两条记录展示了从自然语言提取字段并写入任务状态的过程。等级规则和默认值由应用配置，表中内容为课件的预期记录。

## 4. 典型应用

| 场景 | 排序依据 |
| --- | --- |
| 自动化客服 | 服务中断或重大故障优先于常规请求 |
| 云资源调度 | 高峰期优先保障关键应用 |
| 自动驾驶 | 避撞动作优先于常规行驶目标 |
| 金融交易 | 结合市场变化、风险与收益安排候选操作 |
| 项目管理 | 综合时限、依赖、团队资源与目标贡献 |
| 网络安全 | 结合威胁严重程度、潜在影响与资产关键性 |
| 个人助理 | 按用户偏好、截止时间与当前情境安排提醒 |
